### Why `claude plugin eval` was not used

The plan asks for a `claude plugin eval` case. It can't measure these hooks against a local engine:
- the eval runner gives each run its own HOME;
- it passes hook processes only HOME, with no `RUSHDB_*` variables (checked with a probe plugin that dumps its environment);
- a case file may set only `EVAL_*` keys.

So the hooks resolve to `off` in every eval run. The "Recall changes answers" row above is the same with/without comparison, run by hand with `claude -p`. An eval suite could work only with a RushDB project set through `userConfig`, which needs a real key.

### Deviation from the plan: `Stop` is synchronous

The plan (P0-5) asks for `Stop` with `async: true`. In print mode, Claude cancels async hooks at exit: the `Stop` hook was cancelled about 17 ms after it started ("Hook Stop (Stop) cancelled"). Headless `claude -p` runs never captured their turn. With the orchestrator's go, `Stop` is now synchronous with a hard `timeout: 5`.

- The hook makes no network call. It writes the turn to the local outbox and spawns the detached flush, which sends the turn after the hook has returned.
- Headless check after the change: `claude -p` stated a decision, `Stop` finished, and `SessionEnd` ran (status 0). The outbox was empty 3 s later. A second `claude -p` run recalled the decision and named RushDB as its source.
- Per-turn cost: I ran the bundle's `capture` 10 times with a real Stop payload. The times include Node start-up, which is what Claude waits for.
  - Engine up: 67–115 ms (median 80 ms).
  - Engine paused, so every request hangs: 67–85 ms. The 10 turns stayed queued in the outbox. The hook never waits on the network.

### Fixed: Qwen captured its memory catalog instead of the prompt

The real Qwen 0.27.4 chat log writes a `type: "system"`, `subtype: "memory_catalog_snapshot"` record after each prompt, and that record's message has `role: "user"`. The transcript reader took it as the last prompt, so Qwen episodes stored "Current memory catalog…" in place of what the user typed. The fix is in `packages/hooks/src/transcript.ts`: a record whose `type` is set to anything other than `user` is never a prompt. The Qwen fixture now has the recorded 0.27.4 shape, with ids, paths and long text trimmed. After the fix, the live run stored the real prompt.

### Qwen quirk

Installing from a local marketplace folder leaves Qwen's converted copy (`plugin<sha256>/`) in that folder. `scripts/smoke/qwen.sh` removes it. A GitHub install puts it in Qwen's own clone.
