### `claude plugin eval`

The eval runner gives each run its own HOME and passes hook processes only HOME: no `RUSHDB_*` variables. A case may set only `EVAL_*` keys. So the hooks resolve to `off`, and an eval case can't reach a local engine. I checked this with an env-dump probe plugin. The table above has the same with/without comparison, run by hand. An eval suite would only work against a RushDB project set through `userConfig`, which needs a real key.

### Finding for the orchestrator: async `Stop` in `claude -p`

In print mode, Claude cancels the async `Stop` hook about 17 ms after it starts ("Hook Stop (Stop) cancelled"). So headless `claude -p` runs never capture their turn. Interactive sessions capture normally. A synchronous `Stop` costs 58–69 ms per turn here: capture only writes to the outbox and spawns the detached flush. The plan asks for `async: true`, so this branch keeps it. Changing it is a one-line change in `scripts/targets/claude.ts`.

### Fixed: Qwen captured its memory catalog instead of the prompt

The real Qwen 0.27.4 chat log writes a `type: "system"`, `subtype: "memory_catalog_snapshot"` record after each prompt, and that record's message has `role: "user"`. The transcript reader took it as the last prompt, so Qwen episodes stored "Current memory catalog…" in place of what the user typed. The fix is in `packages/hooks/src/transcript.ts`: a record whose `type` is set to anything other than `user` is never a prompt. The Qwen fixture now has the recorded 0.27.4 shape, with ids, paths and long text trimmed. After the fix, the live run stored the real prompt.

### Qwen quirk

Installing from a local marketplace folder leaves Qwen's converted copy (`plugin<sha256>/`) in that folder. `scripts/smoke/qwen.sh` removes it. A GitHub install puts it in Qwen's own clone.

- **Hosted MCP sign-in** in Claude Code and in Qwen (`/mcp` → Authenticate), with a RushDB account: confirm that OAuth completes and the tools list.
- **D6**: the privacy policy URL. Setting `urls.privacyPolicy` in `shared/listing.json` makes strict directory validation pass, and the CI step can then become blocking.
